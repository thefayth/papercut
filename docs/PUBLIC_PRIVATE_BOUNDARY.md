# Public / Private Boundary

## Public Surface

The public repository may contain:

- README and project brief
- public-safe diagrams
- public-safe brand notes
- public-safe poster assets
- status and roadmap
- commercial-use policy
- WordPress page draft
- privacy review and launch checklist

## Private Engine

The private engine must not be published:

- source code
- private prompts
- agent instructions
- credentials
- environment files
- customer data
- personal records
- signatures
- uploads
- inbound or outbound faxes
- generated packets
- private screenshots
- run histories
- vault data
- deployment configuration
- operational infrastructure

## Dispatch Boundary

Public demos stop at explanation. Real dispatch is private and gated.

Live email, fax, portal, ATS, or worker dispatch requires:

- authenticated workspace access
- provider configuration
- review-only mode disabled for that environment
- destination approval
- per-item approval
- receipt capture

## WordPress Boundary

FaithCheltenham.com can host a polished product page that links to the public
GitHub surface. WordPress should not expose private app routes, credentials,
operator screenshots, packet artifacts, or private records.
